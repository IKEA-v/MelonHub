# MelonHub 代码基线需求清单与原规格对照

版本：1.0；日期：2026-11-12；适用基线：当前源码与 Flyway V7。

本清单配合《概要设计说明书》使用。按项目本次编写指示，以现有代码的业务含义为设计依据，保留原《统一权限系统软件需求说明书》供对照。下列 CF、CN 编号是本次从代码整理出的校正需求编号，不冒充原文 FR、NFR 编号，也不表示所有质量目标已完成验收。原文未覆盖的已实现功能补入清单。

## 3 原需求与分析模型的使用规则

原 FR01–FR15 与 NFR01–NFR12 全部在概要设计第 9.1 节保留对照；不把改写后的需求继续无标识地称作原需求。原需求中的部门权限域、人员单主部门、动态管理等级、平台业务用户登录、调岗先全部回收、HR 自动同步和 OA 协议均不作为当前实现能力。

原文图4-1 至图4-9 的编号仍用于说明分析模型来源。图4-1、图4-6、图4-7 至图4-9 的业务含义需经过软件级模型校正后才能转换；不得把原图作为当前源码的准确类图或数据流图。原 UC01–UC15 的引用只表达来源，不构成原用例全部已实现的验收声明。

## 4 验收口径

建议性能场景采用至少 21 个软件、1 万用户、持续 200 请求/秒运行 10 分钟，服务端 p95 ≤ 200 毫秒、p99 ≤ 500 毫秒；该口径继承原需求的建议值，需固定数据库网络距离、机器资源、是否启用 Redis、命中率与限流设置后再确认。当前云链路无本轮压测证据，不引用历史本机成绩替代。

可靠性验收须覆盖缓存关闭/故障、数据库失败、外盒重复投递、租约失效、分配到期、复核与续期并发。恢复目标与保留期由运行配置和项目方确认；本文只记录架构落实方向。
