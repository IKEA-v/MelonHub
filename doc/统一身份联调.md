# MelonHub 与课程管理系统统一身份联调

课程管理系统仓库的 API 契约把统一身份认证服务作为独立服务。MelonHub 现在提供课程管理系统实际使用的统一身份接口，接口根路径为 `/auth`，管理控制台仍使用 `/api/auth`。

## 已实现接口

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/auth/login` | 校验登录名和密码，返回 JWT `accessToken`、`tokenType`、`expiresIn` |
| POST | `/auth/logout` | 撤销当前 JWT |
| GET | `/auth/me` | 返回 `subject`、`roles`、`permissions`、姓名和工号 |
| GET | `/auth/permissions/{permission}` | 查询前端菜单或按钮权限 |
| GET | `/auth/api-permissions/{operationId}` | 查询课程 API 的全局权限 |
| GET | `/auth/departments` | 分页查询部门，支持 `keyword`、`parentId`、`page`、`pageSize` |
| GET | `/auth/departments/{departmentId}/users` | 分页查询部门用户 |
| GET | `/auth/users/{userId}` | 按统一身份用户标识查询姓名和工号 |

成功响应和错误响应遵循课程管理系统 OpenAPI 中的字段约定。错误响应使用 `{ code, message }`，JWT 只携带身份声明，不携带角色和权限。

## 课程系统配置

课程管理系统后端的 `IDENTITY_BASE_URL` 应填写 MelonHub 对外地址，例如：

```text
IDENTITY_BASE_URL=http://<MelonHub服务器地址>
```

课程管理系统前端的 `VITE_IDENTITY_BASE_URL` 也应填写浏览器可访问的同一个地址。MelonHub 的 `CORS_ALLOWED_ORIGINS` 填课程前端的实际 Origin。联调阶段可以设置为 `*`，生产环境应改成明确来源。

课程系统的目标系统标识固定为 `course-project-management`。登录请求必须包含：

```json
{
  "username": "工号或学号",
  "password": "测试密码",
  "systems": ["course-project-management"]
}
```

## 建立课程系统权限

管理员登录凭据只从根目录 `.env` 读取。准备一个不提交到 Git 的 CSV，例如：

```csv
name,username,password,email,role
联调教师,T10001,只在本地保存的测试密码,teacher@example.invalid,teacher
联调学生,S10001,只在本地保存的测试密码,student@example.invalid,student
```

执行：

```powershell
./scripts/setup-course-integration.ps1 -BaseUrl http://127.0.0.1:8080 -UsersFile .local/course-users.csv
```

脚本会幂等准备以下数据：

- 部门 `course`
- 软件 `course-project-management`
- 课程系统的后端权限码 `TC`、`TE`、`TD`、`TCM`、`CV`、`CR`、`CRS`、`CE`、`CD`、`CC`、`CTM`、`TV`、`TEC`、`TEE`、`TED`、`AV`、`UL`
- 前端菜单和按钮权限码，例如 `MCO`、`MTR`、`MTE`、`MLG`、`MCOR`、`MCOE`
- `admin`、`teacher`、`student` 三个角色
- CSV 中的联调用户、BCrypt 登录凭据和角色分配

脚本分批导入，每批最多 500 个用户。密码只发送到 MelonHub 的 HTTPS/API 连接并保存为 BCrypt 摘要，不写入日志。

## 联调顺序

1. 启动 MelonHub 后端并检查 `/api/health`。
2. 执行课程权限初始化脚本。
3. 用课程前端的 `VITE_IDENTITY_BASE_URL` 指向 MelonHub 地址重新构建课程前端。
4. 用课程后端的 `IDENTITY_BASE_URL` 指向 MelonHub 地址重新部署课程后端。
5. 用联调教师和联调学生账号调用 `/auth/login`。
6. 把 MelonHub 对外可访问的 IP 或域名提供给老师。
7. 先验证 `/auth/login`、`/auth/me`、`/auth/permissions/MCO`、`/auth/departments`，再验证课程系统业务接口。

## 当前边界

课程管理系统自己的业务数据库和业务 API 仍由课程项目仓库负责。MelonHub 只提供统一身份、组织查询和权限判断。课程系统的对象级权限仍由课程系统 Service 根据课程、教学班和小组关系判断。

课程系统可以直接使用课程项目提供的后端镜像。MelonHub 的 Redis 不是联调前置条件，缓存关闭时权限判断回退 MySQL，适合当前联调阶段。
