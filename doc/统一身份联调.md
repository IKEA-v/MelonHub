# MelonHub 与课程管理系统统一身份联调

课程管理系统仓库的 API 契约把统一身份认证服务作为独立服务。MelonHub 提供下列统一身份接口；老师系统当前实际调用范围见 [课程权限接入核对](课程权限接入核对.md)，接口根路径为 `/auth`，管理控制台仍使用 `/api/auth`。

## 已实现接口

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/auth/login` | 校验登录名和密码，返回 JWT `accessToken`、`tokenType`、`expiresIn` |
| POST | `/auth/logout` | 撤销当前 JWT |
| GET | `/auth/me` | 返回 `subject`、`roles`、`permissions`、姓名和工号 |
| GET | `/auth/audit-logs` | 分页查询已入库的课程业务日志，要求 `AV` 且受授权部门限制 |
| GET | `/auth/permissions/{permission}` | 查询前端菜单或按钮权限 |
| GET | `/auth/api-permissions/{operationId}` | 查询课程 API 的全局权限 |
| GET | `/auth/departments` | 分页查询部门，支持 `keyword`、`parentId`、`page`、`pageSize` |
| GET | `/auth/departments/{departmentId}/users` | 分页查询部门用户 |
| GET | `/auth/users/{userId}` | 按统一身份用户标识查询姓名和工号 |

字段以仓库中的 [统一身份 OpenAPI](identity-openapi.yaml) 为准。错误响应包含 `code`、`message` 与请求编号。JWT 只携带身份声明，角色与权限由后端实时查询。

## 浏览器中查看单项权限响应

在课程系统打开 F12 → Network（网络），选择实际发出的 `/auth/permissions/{permission}` 请求，在 Response（响应）中查看返回值。例如教师查询权限码为 `TV`，某个无该权限的账号会收到：

```json
{"permission":"TV","allowed":false}
```

响应仅含本次校验的权限码与允许结果，不返回姓名、账号、角色或整份权限清单。`allowed` 是课程前端现有的判断字段，不能删掉后只回传字符串。权限码大小写保留原值。

当前课程教师管理菜单查询的是 `MTE`，与教师业务查询权限 `TV` 不同。只能在浏览器实际发出权限请求时看到对应响应；课程后端内部读取 `/auth/me` 的请求不会自动出现在浏览器 Network 中，也不能保证每个业务按钮都会额外发出单项权限请求。本次不修改老师课程前端，不添加 Console 打印。

## 课程系统配置

当前 Swarm 中，课程后端通过 `APP_IDENTITY_BASE_URL` 调用 MelonHub，配置形式为：

```text
APP_IDENTITY_BASE_URL=http://<MelonHub服务器地址>:18080
```

课程页面使用服务器 `18090`。登录和课程业务请求经同源 `/api/` 转给课程后端。菜单权限和部门查询使用同源 `/auth/permissions/...`、`/auth/departments`，由课程前端的 Nginx 转给 Swarm 网络中的 MelonHub。课程后端直接调用 `18080` 完成统一身份认证，经 `/auth/me` 读取权限集合并在本地授权组件中检查课程操作；本次运行包未发现 `/auth/api-permissions/{operationId}` 调用。现行链路使用同源代理和服务间调用。

课程系统的目标系统标识固定为 `course-project-management`。登录请求必须包含：

```json
{
  "username": "工号或学号",
  "password": "测试密码",
  "systems": ["course-project-management"]
}
```

## 首次导入课程账号及权限

已部署的验收环境直接使用当前课程账号登录。只有需要初始化联调账号时，才按实际确认的账号和密码准备一次性的私有 CSV。管理员凭据从根目录 `.env` 读取。CSV 字段如下。

```csv
name,username,password,email,role
联调教师,T10001,只在本地保存的测试密码,teacher@example.invalid,teacher
联调学生,S10001,只在本地保存的测试密码,student@example.invalid,student
```

执行：

```powershell
./scripts/setup-course-integration.ps1 -BaseUrl 'http://<MelonHub服务器地址>:18080' -UsersFile '<本次导入的临时文件路径>'
```

脚本会幂等准备以下数据：

- 部门 `course`
- 软件 `course-project-management`
- 课程系统的后端权限码 `TC`、`TE`、`TD`、`TCM`、`CV`、`CR`、`CRS`、`CE`、`CD`、`CC`、`CTM`、`TV`、`TEC`、`TEE`、`TED`、`AV`、`UL`
- 前端菜单和按钮权限码，例如 `MCO`、`MTR`、`MTE`、`MLG`、`MCOR`、`MCOE`
- `admin`、`teacher`、`student` 三个角色
- CSV 中的联调用户、BCrypt 登录凭据和角色分配

脚本会刷新所列角色权限及 CSV 用户的角色和凭据。每批最多 500 个用户，服务器保存 BCrypt 摘要。导入结束后移走临时文件。当前课程验收密码只在 Git 忽略的根目录 `.env` 中维护。

## 联调顺序

1. 检查两套系统的 Swarm 服务状态和 MelonHub 的 `/api/health`。
2. 在浏览器打开服务器 `18090`，选择对应身份并使用当前联调账号登录。
3. 核对课程 `/api/me` 返回的角色，并抽查菜单权限和部门查询。
4. 用验收账号实际调用一项受权限保护的课程业务接口，核对 MelonHub 的决定和课程后端的处理结果。

## 当前边界

课程管理系统自己的业务数据库和业务 API 仍由课程项目仓库负责。MelonHub 只提供统一身份、组织查询和权限判断。课程系统的对象级权限仍由课程系统 Service 根据课程、教学班和小组关系判断。

课程系统可以直接使用课程项目提供的后端镜像。MelonHub 的 Redis 不是联调前置条件，缓存关闭时权限判断回退 MySQL，适合当前联调阶段。
