# MelonHub 面向对象设计答辩

## A. 严格分离的结构化设计与基于 DDD 的体系结构

### 问题 1 · MelonHub 如何在一套工程里同时严格实现“结构化一套后端 + DDD 一套后端”？

**答。** MelonHub 参考联调示例项目 `CourseProjectMgt` 的单模块双策略架构，通过 `service.port` 定义 10 个统一用例端口接口，控制器（`controller`）、鉴权过滤器（`security`）和初始化器只依赖端口，不依赖具体实现；启动时通过 `melonhub.backend-strategy=structured|ddd` 经 Spring `@ConditionalOnProperty` 排他激活一整套后端：

- **纯结构化后端（`service.structured`）**：10 个 `Structured*Service` 严格采用事务脚本（Transaction Script）与纯静态过程函数（如 [StructuredAdminHierarchyProcedures](../backend/src/main/java/com/melonhub/rbac/service/structured/StructuredAdminHierarchyProcedures.java)），按用例步骤直接编排 DAO、事务、缓存和审计，**彻底移除了原先混用的领域对象**。
- **纯 DDD 后端（`service.ddd`）**：严格按「零框架领域层 `domain`（9 个值对象/领域策略 + 12 个聚合根 + 11 个纯 Java 仓储/网关端口）→ 薄应用服务层 `application`（10 个 `Ddd*Service`）→ 基础设施适配层 `infrastructure`（10 个适配器）」三层解耦，依赖全部向内指向领域层。
- **自动化边界守护**：[ArchitectureBoundaryUnitTest](../backend/src/test/java/com/melonhub/rbac/requirements/nfr_reliability/ArchitectureBoundaryUnitTest.java) 自动扫描全部主源码，证明结构化包零 DDD 导入、`ddd.domain` 零 Spring/JPA/DAO 导入、`ddd.application` 不绕过仓储端口；[BackendStrategyWiringUnitTest](../backend/src/test/java/com/melonhub/rbac/requirements/nfr_reliability/BackendStrategyWiringUnitTest.java) 在 Spring 容器中实测两套策略均可独立装配且零冲突。

### 问题 2 · 同一个业务用例在“纯结构化”和“纯 DDD”里有哪些本质差异？

**答。** 拿系统里任意一个核心 API 都能直接左右对照：

| 比较维度 | 纯结构化后端（`service.structured`） | 纯 DDD 后端（`service.ddd`） |
| --- | --- | --- |
| **代码分解依据** | 用例输入 → 顺序校验 → 查库/写库 → 响应输出（面向过程/数据流） | 限界上下文 → 聚合根/值对象不变量 → 领域仓储端口（面向领域模型） |
| **分级管理员树校验** | [StructuredAuthService](../backend/src/main/java/com/melonhub/rbac/service/structured/StructuredAuthService.java) 调用无状态静态过程集 [StructuredAdminHierarchyProcedures](../backend/src/main/java/com/melonhub/rbac/service/structured/StructuredAdminHierarchyProcedures.java) 直接遍历 `AccountNode` 列表 | [DddAuthService](../backend/src/main/java/com/melonhub/rbac/service/ddd/application/DddAuthService.java) 加载聚合根 [AdminHierarchy](../backend/src/main/java/com/melonhub/rbac/service/ddd/domain/model/AdminHierarchy.java) 与值对象 [AdminScope](../backend/src/main/java/com/melonhub/rbac/service/ddd/domain/value/AdminScope.java)，由对象自检创建/更新/删除/角色一致性不变量 |
| **统一身份 API 权限查询** | [StructuredIdentityService](../backend/src/main/java/com/melonhub/rbac/service/structured/StructuredIdentityService.java) 在同一方法内串行验签、查会话、查映射、查权限 | [DddIdentityService](../backend/src/main/java/com/melonhub/rbac/service/ddd/application/DddIdentityService.java) 经端口获取用户后委托值对象 [CoursePermissionCatalog](../backend/src/main/java/com/melonhub/rbac/service/ddd/domain/value/CoursePermissionCatalog.java) 与聚合根 [IdentityAccountAggregate](../backend/src/main/java/com/melonhub/rbac/service/ddd/domain/model/IdentityAccountAggregate.java) 决策 |
| **隔离域授权与上下文** | [StructuredRbacService](../backend/src/main/java/com/melonhub/rbac/service/structured/StructuredRbacService.java) / [StructuredContextService](../backend/src/main/java/com/melonhub/rbac/service/structured/StructuredContextService.java) 直接操作 DAO 与缓存 | [DomainAuthorizationAggregate](../backend/src/main/java/com/melonhub/rbac/service/ddd/domain/model/DomainAuthorizationAggregate.java)、[UserMembershipAggregate](../backend/src/main/java/com/melonhub/rbac/service/ddd/domain/model/UserMembershipAggregate.java)、[PermissionContextAggregate](../backend/src/main/java/com/melonhub/rbac/service/ddd/domain/model/PermissionContextAggregate.java) 集中守护三层有效期、移出部门清脏授权、部门切换保护与模拟诊断 |
| **如何保证行为 100% 等价** | 全部 30 个集成测试经 `service.port` 注入，可通过 `-Dmelonhub.backend-strategy=structured` 或 `ddd` 双跑；另配双策略等价单测 [DddDomainAndDualStrategyParityUnitTest](../backend/src/test/java/com/melonhub/rbac/requirements/nfr_reliability/DddDomainAndDualStrategyParityUnitTest.java) | 同上，且所有领域聚合根均可在零 Spring、零数据库下做毫秒级纯内存单测 |

## B. 具体 API 中的 GRASP 原则

### 问题 3 · 创建管理员时，什么对象应该判断下级范围是否合法？

**答。Information Expert（信息专家）。** 在 DDD 后端中，[AdminHierarchy](../backend/src/main/java/com/melonhub/rbac/service/ddd/domain/model/AdminHierarchy.java) 与 [AdminScope](../backend/src/main/java/com/melonhub/rbac/service/ddd/domain/value/AdminScope.java) 同时掌握全部节点的父子拓扑、角色功能集合和部门/软件范围，因此由 `validateCreate()` / `validateUpdate()` / `violations()` 集中判断循环、叶子约束与上下级范围包含关系，[DddAuthService](../backend/src/main/java/com/melonhub/rbac/service/ddd/application/DddAuthService.java) 只负责锁表、事务与审计。

### 问题 4 · 双策略架构本身集中体现了哪些 GRASP 原则？

**答。Polymorphism（多态）、Indirection（中介）、Protected Variations（受保护变化）与 Low Coupling（低耦合）。**

- **Protected Variations & Polymorphism**：将“结构化实现 vs DDD 实现”这一架构变化点封装在 `service.port` 的 10 个稳定接口背后，两套实现以多态方式履行同一契约，控制器与鉴权过滤器零感知、零改动。
- **Indirection & Pure Fabrication**：DDD 基础设施层的 9 个 `Jpa*Adapter` 和 [SpringPlatformGatewaysAdapter](../backend/src/main/java/com/melonhub/rbac/service/ddd/infrastructure/SpringPlatformGatewaysAdapter.java) 是典型的纯虚构中介，阻断了领域层对 JPA、Redis、BCrypt、HTTP Client 的直接依赖。
- **Controller & Low Coupling**：如 [IdentityController](../backend/src/main/java/com/melonhub/rbac/controller/IdentityController.java) 只负责协议适配并委派 [IdentityUseCase](../backend/src/main/java/com/melonhub/rbac/service/port/IdentityUseCase.java)，不直接接触数据库、JWT 实现细节或具体后端策略。

### 问题 5 · 为什么分级管理员与核心授权既有纯单测，又有双策略等价测试和集成测试？

**答。** 三层测试各司其职：
1. **纯领域/过程单测**（如 [R19_AdminTreeUnitTest](../backend/src/test/java/com/melonhub/rbac/requirements/e_admin_security/R19_AdminTreeUnitTest.java)）：零数据库毫秒级验证 `AdminHierarchy` 与 `StructuredAdminHierarchyProcedures` 对循环、越权、叶子节点的判定完全一致。
2. **架构边界与装配/等价单测**（[ArchitectureBoundaryUnitTest](../backend/src/test/java/com/melonhub/rbac/requirements/nfr_reliability/ArchitectureBoundaryUnitTest.java)、[BackendStrategyWiringUnitTest](../backend/src/test/java/com/melonhub/rbac/requirements/nfr_reliability/BackendStrategyWiringUnitTest.java)、[DddDomainAndDualStrategyParityUnitTest](../backend/src/test/java/com/melonhub/rbac/requirements/nfr_reliability/DddDomainAndDualStrategyParityUnitTest.java)）：验证边界零污染、Spring 双策略独立装配，以及移出部门清脏授权、跨部门切换拒绝、审计链 v1/v2 哈希和健康检查契约在两套后端下完全一致。
3. **数据库与 HTTP 集成测试**（如 [R19_AdminTreeIntegrationTest](../backend/src/test/java/com/melonhub/rbac/requirements/e_admin_security/R19_AdminTreeIntegrationTest.java)）：验证真实事务、悲观锁、Flyway `V1–V16` 外键约束与端到端 HTTP 契约。
