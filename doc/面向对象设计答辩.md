# MelonHub 面向对象设计答辩

## A. 结构化设计和基于 DDD 的体系结构

### 问题 1 · 两种方法分别从哪里开始划分代码？

**答。** 结构化设计从系统功能和数据流分解职责，围绕一个用例安排认证、查询、判断和响应。DDD 从领域概念、业务边界和不变量出发。应用服务编排用例，领域对象封装自己掌握的规则，仓储端口隔离持久化。

MelonHub 的 `GET /auth/api-permissions/{operationId}` 适合说明按过程组织的设计。控制器适配 HTTP，`IdentityService.checkApiPermission` 验证会话、把操作标识映射到权限码，再从 `IdentityDao` 读取当前用户的权限。各步骤直接对应请求的数据流。 [权限查询用例](../backend/src/main/java/com/melonhub/rbac/identity/IdentityService.java)

### 问题 2 · MelonHub 哪个例子体现了把规则放回领域模型？

**答。** `POST /api/admin/accounts` 先由 `AuthService.createAccount` 协调锁、上级授权、事务写入和审计。`AdminTree` 集中校验管理员层级、循环、部门管理员叶子约束，以及下级范围不得超出上级等不变量。这样可以用一组账号与角色功能直接测试规则，无需运行 HTTP 服务或数据库。该用例使用了 DDD 的领域建模思想，MelonHub 目前采用统一的 Controller、Service 与 DAO 运行结构。 [账号用例](../backend/src/main/java/com/melonhub/rbac/service/AuthService.java) · [管理员树](../backend/src/main/java/com/melonhub/rbac/service/AdminTree.java)

| 比较维度 | 结构化视角 | DDD 视角 |
| --- | --- | --- |
| 分解依据 | 用例输入、处理步骤、输出数据 | 领域边界、对象职责、不变量 |
| 业务规则归属 | 服务过程按顺序协调判断 | 对象持有判断所需状态并维护不变量 |
| MelonHub 例子 | 统一身份 API 权限查询 | 分级管理员树的范围与层级规则 |
| 如何验证 | 用契约用例核对允许、拒绝和错误响应 | 用领域测试验证树规则，再用接口测试核对持久化及权限 |

## B. 具体 API 中的 GRASP 原则

### 问题 3 · 创建管理员时，什么对象应该判断下级范围是否合法？

**答。Information Expert（信息专家）。** `AdminTree` 同时掌握上级和下级的范围、角色功能以及父子结构。`violations()` 根据这些信息判断下级是否超出上级，以及是否违反部门管理员约束。`AuthService` 在保存前构造候选树并调用校验。这样角色、部门和软件范围的约束可以集中验证。 [AdminTree](../backend/src/main/java/com/melonhub/rbac/service/AdminTree.java) · [领域规则测试](../backend/src/test/java/com/melonhub/rbac/requirements/e_admin_security/R19_AdminTreeUnitTest.java)

### 问题 4 · API 权限查询体现哪些对象职责？

**答。Controller（控制器）与 Low Coupling（低耦合）。** `IdentityController.apiPermission` 接收路径参数和授权头，将用例交给 `IdentityService`。`IdentityDao` 负责基于当前授权数据的查询，控制器不接触数据库。令牌签发校验由 `IdentityTokenService` 承担，权限用例只依赖它提供的校验结果，这个职责分配也体现了 Pure Fabrication（纯虚构）。 [IdentityController](../backend/src/main/java/com/melonhub/rbac/controller/IdentityController.java) · [IdentityTokenService](../backend/src/main/java/com/melonhub/rbac/identity/IdentityTokenService.java)

### 问题 5 · 为什么分级管理员规则既有单测，又有接口集成测试？

**答。** 领域测试验证父子范围、循环和部门管理员类型的边界。接口集成测试验证有权的管理者可以创建下级、范围越界时返回错误，以及规则失败时不会保存账号。两种测试分别验证信息专家的判断和应用服务对规则的执行。 [管理员树集成测试](../backend/src/test/java/com/melonhub/rbac/requirements/e_admin_security/R19_AdminTreeIntegrationTest.java)
